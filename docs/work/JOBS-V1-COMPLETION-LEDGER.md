## Customer outcome and boundaries

One candidate can establish an accurate profile and search policy, discover
fresh eligible jobs, review a grounded application kit, authorize supported
execution, and understand the resulting receipt, employer outcome and cost.
The product goal also includes scoped agent access, recruiter communication
and approved messaging channels; a passing core test does not finish them.

Jobs is independent of the desktop host/overlay and Pinky work. No deploy,
production flag, real application/email/calendar action, paid resource, push
or publication is authorized by the local qualification rounds. Resume
tailoring cannot invent candidate facts. Existing credentials are not a reason
to widen test scope. Current code/local handoffs take precedence over skill
snapshots; use the SSD only for a specific missing historical detail.

## Execution order

1. Complete the actual candidate journey locally, fail at any broken boundary,
   fix only a reproduced cause, and preserve negative authority tests.
2. Stitch the synthetic source/packet/approval/fixture-ATS/receipt path without
   inventing a success, weakening certification or contacting a real employer.
3. Qualify isolated object storage, provider/model and mailbox integrations using
   dedicated resources; resource/authority holds do not block independent code.
4. Finish scoped agent access, C2C, approved business messaging and client access
   as independently reviewed increments, sharing the same server authority.
5. Qualify the exact release tip/artifacts, infrastructure/capacity, billing and
   rollback/kill-switch evidence. Promote only under separate authorization.

The differentiation targets are verified freshness/fit, accurate tailoring,
trustworthy receipts/recovery, understandable controls and measured cost/latency.
No comparative superiority, production SLO or interview outcome is proven yet.
