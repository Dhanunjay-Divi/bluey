## Founder Post Draft

I built Bluey because live technical work has too much context for a normal chatbot.

During a design review or customer call, the useful answer depends on the transcript, the screen, the doc, the code, and the decisions from earlier sessions. Bluey runs as a desktop overlay and helps answer from those approved sources without forcing you to rebuild the whole prompt from scratch.

It starts free, then uses credits when managed AI, speech, screen analysis, or saved-session search are used.

## Community Post Draft

I have been working on Bluey, a desktop AI copilot for live technical work. The problem I kept hitting: a normal chatbot is smart but does not know what is happening in the current call, screen, doc, or code review.

Bluey tries to make that context first-class. It can answer from approved live transcript, screen context, files, docs, code, and saved session memory. I am looking for feedback from people who spend a lot of time in engineering meetings, design reviews, support calls, or incident reviews.
