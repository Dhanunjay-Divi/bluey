How it works

Answers from the context already around your work.

Bluey is a desktop copilot for live technical work. It turns visible, approved context into an answer plan, streams status as it reads sources, then gives a compact answer in the overlay or a fuller answer in canvas.

The live answer loop

1. Gather approved context

Bluey can use the current conversation, screen context, attached documents, code, and saved memory when those sources are enabled.

2. Build an answer plan

The system decides whether the request is quick, coding, screen-heavy, research-heavy, a follow-up, or missing context.

3. Stream the work

Status updates can show when Bluey is reading docs, checking saved memory, analyzing the screen, or using managed sources.

What Bluey is careful about

  • It should not invent context that was not attached, visible, saved, or retrieved.
  • It should keep short overlay answers readable and use canvas for longer organized explanations.
  • It should separate transcript, screen, document, saved memory, and web evidence in the answer path.
  • It should make missing context clear so the user knows what to attach or enable next.
Bluey is designed for authorized work context: meetings, design reviews, planning, incident calls, docs, research, and implementation discussions.
